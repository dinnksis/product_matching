Ты создаёшь две реалистичные карточки разных продавцов для одного и того же
конкретного товара. Вход содержит доверенное атомарное правило с target=1,
старую синтетическую пару, реальные карточки того же типа и структурный шаблон
человеческой пары.

Правило и label менять нельзя. Разрешено исправить только старое/новое значение
целевого атрибута, если прежнее значение явно не относится к смыслу атрибута
(например, цвет записан как бренд, аромат как цвет, текст как размер). При
исправлении предпочитай значения из source evidence.

Основные требования:

1. Обе карточки описывают один конкретный товар, а не просто товары одного типа.
2. Сохрани одинаковыми идентифицирующие факты: реальный бренд, модель/линейку,
   назначение, конструкцию, состав и другие сведения, определяющие товар.
3. Единственное содержательное расхождение — переданный атомарный атрибут.
   Остальные различия должны быть только продавцовыми: порядок слов, пунктуация,
   регистр, синонимы ключей, единицы в эквивалентной форме, пропущенные поля и
   разная детализация одного факта.
4. Не придумывай бренд. Если целевой концепт не brand/manufacturer, используй
   ровно один бренд из allowed_observed_brands и напиши его одинаково на обеих
   сторонах; если список пуст, не добавляй бренд/производителя вообще. Название цвета,
   материала, страны, размера или назначения никогда не является брендом.
5. Не копируй артикулы, SKU, внутренние ID и случайные числа из примеров.
6. У каждой карточки должно быть 5–20 полезных атрибутов и естественное название
   длиной примерно 5–16 слов. Не делай две стороны одинаковыми по набору ключей.
   Все ключи и значения attributes — только непустые строки: никаких массивов,
   вложенных объектов, чисел JSON, null или boolean.
7. Целевой атрибут обязан присутствовать на обеих сторонах. Продавцы могут
   использовать разные естественные ключи-синонимы; верни их как attribute_key_a
   и attribute_key_b. canonical_attribute_key из правила менять нельзя. На
   стороне A значение original_value, на стороне B new_value.
8. Не добавляй противоречивые зависимые поля. Например, при изменении веса нельзя
   оставлять другой вес в габаритах/комплектации; при изменении модели нельзя
   приписывать спецификации другой модели.
9. Любой общий нецелевой ключ обязан иметь одинаковое значение. Остальные seller-
   различия оформляй разными ключами или отсутствующими полями.
10. В identity_facts перечисли минимум два НЕЦЕЛЕВЫХ факта, подтверждающих один
    товар, даже если продавцы назвали соответствующие ключи по-разному. Никогда
    не называй target concept (например, бренд в brand-rule) identity-якорем.
11. Верни только один JSON-объект без markdown и пояснений вне JSON.
