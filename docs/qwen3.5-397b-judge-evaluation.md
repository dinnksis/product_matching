# Qwen3.5-397B product judge: frozen human validation

## Протокол

- Модель: `Qwen3.5-397B-A17B-FP8` через OpenAI-compatible vLLM.
- Prompt: [`prompts/qwen3_5_product_match_judge_v1.md`](../prompts/qwen3_5_product_match_judge_v1.md).
- Полный объём: 58 985 пар (`12 000 IID + 5 814 hard + 41 171 OOD`).
- Thinking отключён; модель принудительно выбирает только `0` или `1`.
- Непрерывный `predict` — softmax между возвращёнными logprob токенов `1` и
  `0`, поэтому метрика не зависит от текстового округления ответа.
- Temperature `0`, `top_logprobs=5`, один порядок пары.
- SHA-256 prompt:
  `dd0d43f197d1ce446c789d486f187281208a0515b5ec093a653dcd7e1d79f9f9`.

Полные артефакты находятся в `reports/qwen3_5_397b_judge_v1/`:
`summary.json`, `per_category_metrics.csv` и ignored Parquet с predictions.

существенно полезнее явной словесной инструкции.

## Почему hard AP низкий

### 1. Hard validation намеренно построена против наблюдаемых сигналов

Hard — не случайная более сложная IID-выборка. Из 5 200 anchor-компонентов:

- 2 600 (`50%` anchors) выбраны по максимальной `lexical_hardness`: это
  положительные пары с минимальным сходством текста и отрицательные с
  максимальным;
- 2 080 (`40%`) — самые уверенные ошибки исходного MiniLM v1;
- 520 (`10%`) — максимальное расхождение MiniLM/light model или order gap;
- ещё 614 строк — остальные пары выбранных компонент.

Иными словами, выборка использует истинный `target`, чтобы намеренно отбирать
пары, на которых обычная связь «больше наблюдаемого сходства → выше вероятность
дубля» нарушена. Поэтому hard AP нельзя трактовать как оценку ожидаемого
качества на обычном потоке.

Разбиение результата Qwen по причине отбора:

| Selection reason | Pairs | Prevalence | Qwen overall AP |
| --- | ---: | ---: | ---: |
| `lexical_surprise` | 2 600 | 0.119 | 0.112 |
| `confident_minilm_v1_error` | 2 080 | 0.301 | 0.229 |
| `component_companion` | 614 | 0.187 | 0.609 |
| `model_disagreement_or_order_gap` | 520 | 0.829 | 0.973 |

Первые две причины составляют 4 680 строк (`80.5%` hard). Вместе на них Qwen
имеет overall AP `0.174` и ROC-AUC `0.420`. На двух остальных группах вместе —
overall AP `0.883` и ROC-AUC `0.882`. Главный провал сосредоточен именно в
label-conditioned adversarial anchors, а не равномерно во всех сложных парах.

### 2. В adversarial anchors много меток, противоречащих доступному тексту

Среди самых уверенных ошибок Qwen встречаются положительные human labels для:

- металлической машинки BMW против модели Toyota Land Cruiser;
- фитинга Camozzi против тормозного шланга Patron;
- акварельных красок против гуаши;
- тормозных колодок, шин, автокрасок и деталей с разными точными артикулами,
  размерами или назначением;
- разных часов, сумок, украшений и обувных моделей.

Одновременно среди отрицательных human labels есть визуально точные текстовые
дубли:

- MSI Stealth `9S7-15F212-086` с тем же полным part number;
- струны Ernie Ball `2146`;
- Nivea «Жемчужная красота», стик `50 мл`;
- автомат EKF `MCB4729-1-16C`;
- одинаковые модели Bresser Junior `6×21`, Kuusamo Rasanen `70/10`,
  Olympia `CTA1152` и другие.

Это не доказывает ошибку каждой такой human-метки: часть различий могла быть на
изображении или в недоступном источнике. Но по переданным `product_text` Qwen
следует восстановленной инструкции логично, а воспроизвести target невозможно.

### 3. Часть положительных пар неразрешима без изображения или каталожной связи

Особенно это видно в обуви и аксессуарах. Одна карточка может содержать только
`ботинки Tendance`, `кроссовки Nike` или `рюкзак`, вторая — конкретную модель.
Организаторы могли видеть одинаковые изображения или общий скрытый catalog ID.
Prompt требует доказать базовую модель и при недостатке данных безопасно ставит
`0`. Поэтому текстовый judge закономерно не воспроизводит такие positives.

Худшие category AP подтверждают этот эффект:

| Категория | Prevalence | Qwen AP | Ответ `1` при score ≥ 0.5 |
| --- | ---: | ---: | ---: |
| Обувь | 0.092 | 0.073 | 0.015 |
| Галантерея и аксессуары | 0.159 | 0.137 | 0.026 |
| Автотовары | 0.184 | 0.156 | 0.044 |
| Спорт и отдых | 0.267 | 0.186 | 0.140 |

В этих категориях hard-положительные пары часто либо слишком общие, либо явно
конфликтуют по модели/конструкции.

### 4. Prompt и scoring дополнительно консервативны

При пороге `0.5` Qwen предсказывает positive только для `13.1%` hard-пар при
истинной prevalence `25.5%`; recall равен `22.8%`, precision — `44.2%`.
Это ожидаемо из правила «нет модельного якоря → низкий score».

Однако консервативный порог не является главным объяснением низкого AP: AP не
зависит от выбора порога, а hard ROC-AUC тоже низок (`0.571`). Основная проблема
— реальные rank inversions в label-conditioned/noisy anchors.

FP8 logits и forced binary choice дают только 174 уникальных score на 5 814
hard-парах. Крупнейший tie содержит `1.6%` строк. Это может немного ухудшать
тонкое ранжирование, но слишком мало, чтобы объяснить падение IID `0.689 →`
hard `0.349`.

## Ручной аудит 200 hard-ошибок

Из ошибок при пороге `predict >= 0.5` фиксированно и воспроизводимо выбраны
`100` случайных FN из `1 143` и `100` случайных FP из `426` (seed `20260817`).
Для каждой пары просмотрены полные `product_text`, после чего она отнесена в
один из четырёх взаимоисключающих классов:

- `qwen_error`: target можно получить из текста; judge ошибся;
- `text_insufficient`: target может быть верен, но нужного изображения,
  варианта или каталожной связи в тексте нет;
- `label_conflict`: target выглядит противоречащим доступному тексту и
  восстановленным правилам;
- `policy_ambiguous`: граница варианта или конфликт полей допускает разные
  разумные решения.

| Тип ошибки | `qwen_error` | `text_insufficient` | `label_conflict` | `policy_ambiguous` |
| --- | ---: | ---: | ---: | ---: |
| FN, n=100 | 27 | 23 | 43 | 7 |
| FP, n=100 | 30 | 13 | 54 | 3 |

Поскольку FN и FP сэмплировались отдельно, общую долю нужно взвешивать на их
реальные объёмы. Оценка состава всех `1 569` threshold-ошибок:

| Причина | Взвешенная доля | Оценка числа пар | 95% stratified bootstrap interval |
| --- | ---: | ---: | ---: |
| Ошибка Qwen, потенциально исправимая по тексту | 27.8% | 436 | 21.2–34.7% |
| Видимый конфликт human target с текстом/правилами | 46.0% | 722 | 38.4–53.5% |
| Текста недостаточно | 20.3% | 318 | 14.2–26.7% |
| Неоднозначна сама policy | 5.9% | 93 | 2.5–9.9% |

Это ручная экспертная оценка, а не доказательство ошибок разметчиков: в
`label_conflict` могут находиться пары, решённые организаторами по изображениям
или скрытому каталожному контексту. Но эта часть не воспроизводима text-only
prompt без утечки target.

Основные настоящие ошибки judge:

- FN: пропуск точного редкого названия/модели или физического fingerprint и
  неудачное разрешение одного шумного поля против нескольких сильных якорей;
- FP: игнорирование суффикса модели, цвета/формулы/возраста, количества,
  комплекта, ревизии, состояния used/new или персонализации;
- FP: generic-overmatch по бренду, типу и общему описанию без двухстороннего
  модельного якоря.

При фантастическом исправлении всех `qwen_error` и отсутствии регрессий
threshold accuracy выросла бы примерно с `73.0%` до `80.5%`. Это верхняя
оценка именно для accuracy при пороге, не для AP: hard AP определяется полным
ранжированием и из этих 200 ошибок напрямую не восстанавливается.

Размеченный аудит находится в
`reports/qwen3_5_397b_judge_v1/hard_manual_audit_200_labeled.csv`; исходные
решения без дублирования больших текстов — в соседнем TSV.

## Candidate prompt v2

[`prompts/qwen3_5_product_match_judge_v2.md`](../prompts/qwen3_5_product_match_judge_v2.md)
на 20% короче v1 по байтам и превращает правила в четыре последовательных
gate: сущность → якорь → явные конфликты → итог. Он дополнительно фиксирует
найденные в аудите случаи:

- один точный код только с одной стороны не подтверждается generic-карточкой;
- буквенно-цифровые суффиксы, revision/year, used/new и персонализация важны;
- количество означает продаваемые единицы, а не только общий объём;
- exact anchor плюс несколько совпадающих полей сильнее одного явно шумного
  marketplace-атрибута;
- общий OEM compatibility code не склеивает replacement-товары разных
  производителей;
- generic изображения и сюжеты нельзя угадывать по отсутствующей картинке.

Это пока кандидат, а не подтверждённое улучшение: локальный vLLM endpoint
`127.0.0.1:8193` после аудита был недоступен. Сравнивать v2 нужно на отдельной
выборке, исключающей эти 200 разобранных ошибок; primary-критерий — IID macro
AP, hard используется как secondary stress-test.

Такой holdout уже зафиксирован в `prepared/qwen_prompt_v2_holdout/human`: по
`2 000` стратифицированных пар на split, seed `20260818`; из hard заранее
исключены все 200 audited пар. Reference v1 на нём:

| Split | v1 macro AP | v1 overall AP |
| --- | ---: | ---: |
| IID | 0.713769 | 0.744294 |
| hard | 0.399318 | 0.389187 |
| OOD | 0.589519 | 0.699633 |

После запуска endpoint v2 измеряется ровно в 10 потоков командой:

```bash
uv run python scripts/evaluate_qwen_product_judge.py \
  --base-url http://127.0.0.1:8193/v1 \
  --data-dir prepared/qwen_prompt_v2_holdout/human \
  --prompt prompts/qwen3_5_product_match_judge_v2.md \
  --output-dir reports/qwen_prompt_v2_holdout/v2 \
  --workers 10
```

## Практический вывод

1. Hard следует оставлять stress-test, а не использовать как основную оценку
   общего качества или для прямого подбора prompt. Primary split остаётся IID.
2. Полезно вручную пересмотреть стратифицированную выборку extreme FN/FP hard с
   изображениями. Отдельно пометить `label conflict`, `text insufficient` и
   настоящую ошибку модели.
3. Для чистого semantic-hard теста нужен дополнительный поднабор, где target
   разрешим из переданного текста. Frozen hard при этом менять не нужно.
4. Qwen лучше использовать как дополнительный семантический score и источник
   disagreement, а не как oracle для замены human labels.
5. После v2 самые обоснованные ablation: небольшой reasoning stage только для
   uncertain pairs, оценка обоих порядков и более гранулярный guided score.
   Few-shot примеры допустимы только из train; validation-примеры в prompt
   будут утечкой. Варианты нужно выбирать по IID, не по label-conditioned hard.
