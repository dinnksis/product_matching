# Аудит качества LLM-разметки

## Короткий вывод

Данные из `data/llm_data` **можно использовать как weak supervision**, но нельзя
считать чистой заменой человеческой разметки.

- На стратифицированной ручной проверке 2000 пар бинарная метка LLM совпала с
  восстановленной человеческой политикой в `1575 / 1961 = 80,3%` разрешимых
  случаев. Ещё 39 пар оставлены как действительно неоднозначные.
- После пересчёта на фактический состав всех 11,19 млн пар оценка согласия выше —
  **89,5%**: корпус на 64,2% состоит из сравнительно лёгких `target = 0`.
- Главная асимметрия: отрицательные метки существенно надёжнее положительных.
  Оценка согласия для бинарного класса `0` — **95,1%**, для класса `1` — только
  **70,7%**.
- `target = 0` выглядит как хороший источник слабых отрицательных примеров
  (**96,8%** согласия). Даже `target = 1` не является gold: около **83,1%**
  разрешимых примеров соответствуют инструкции.
- Дробные положительные оценки особенно опасны: для диапазона `5/9…8/9`
  согласие бинарной положительной метки составляет лишь **60,1%**. Пары `5/9`,
  `6/9` и `7/9` по ручной проверке не достигают даже устойчивого большинства
  настоящих совпадений.

Практический вердикт: использовать raw score, веса, категорийные фильтры и
human-only validation. Не смешивать все `target >= 0.5` с человеческими
положительными примерами как равноценные hard labels.

## Что именно проверено

В `data/llm_data` находятся:

- `items.parquet`: 13 397 761 карточка;
- `matches_llm.parquet`: 11 187 780 пар;
- 20 категорий;
- десять возможных значений `target`: `0`, доли от `1/9` до `8/9`, `1`.

Структурно данные чистые: нет пропусков, self-pairs, повторов неупорядоченных
пар, неразрешённых ID и межкатегорийных пар. Все 11 187 780 пар уникальны.

С human-разметкой провести прямую внешнюю проверку нельзя. Все 711 304 human-ID
присутствуют в общем LLM-каталоге карточек, но ни один из них не используется
как `id1` или `id2` в `matches_llm.parquet`. Поэтому LLM-пары item-disjoint с
human-парами: точных пересечений пар также нет.

## Дизайн ручного аудита

Пары оценивались по [восстановленной человеческой инструкции](inferred-human-matching-guidelines.md),
по полным `name + attributes`, без просмотра исходной LLM-аргументации.
Основная выборка разделена на четыре непересекающихся блока по 500 пар между
четырьмя ревьюерами; у каждой пары было одно первичное решение. Отдельное
перекрытие для оценки согласованности описано ниже.

Выборка построена с seed `20260814`:

1. Для каждой из 20 категорий выделены четыре диапазона:
   `target = 0`, `0 < target < 0.5`, `0.5 < target < 1`, `target = 1`.
2. Из каждого диапазона каждой категории случайно взято по 25 пар.
3. Получено ровно `20 × 4 × 25 = 2000` пар: по 100 на категорию и по 500 на
   диапазон.

Каждой паре присвоено:

- `0` или `1` — решение по восстановленной инструкции;
- `U` — данных действительно недостаточно или поля внутренне противоречат друг
  другу настолько, что выбрать бинарную метку нельзя;
- уверенность `H/M/L`;
- тип ошибки LLM и пояснение, если бинарные решения расходятся.

Для оценки всего корпуса каждая строка получила вес
`число пар в category × band / 25`. 95%-интервалы ниже получены 30 000
стратифицированных bootstrap-перевыборок. Это **sampling-only interval**: он не
учитывает неопределённость самой восстановленной инструкции.

## Основные результаты

| Диапазон | Пар в корпусе | Доля корпуса | Ручной результат | Взвешенное согласие |
|---|---:|---:|---:|---:|
| `target = 0` | 7 184 663 | 64,2% | 480 / 496 | **96,8%** |
| `0 < target < 0.5` | 1 383 550 | 12,4% | 424 / 493 | **86,4%** |
| `0.5 < target < 1` | 1 395 612 | 12,5% | 295 / 492 | **60,1%** |
| `target = 1` | 1 223 955 | 10,9% | 376 / 480 | **83,1%** |
| **Всего** | **11 187 780** | **100%** | **1575 / 1961** | **89,5%** |

`Ручной результат` — correct/resolved в сбалансированной выборке. Последний
столбец пересчитан на фактические размеры страт, поэтому его нельзя получить
простым усреднением предыдущего столбца.

Для общей взвешенной оценки sampling-only 95% interval равен **88,2–90,7%**.
Если все `U` считать ошибками LLM, точечная оценка равна 88,3%; если все считать
верными — 89,6%. Реальная неопределённость шире из-за субъективности сложных
категорий.

При используемом в проекте пороге `target >= 0.5`:

| Бинарная метка LLM | Пар | Взвешенное согласие |
|---|---:|---:|
| `0` | 8 568 213 | **95,1%** |
| `1` | 2 619 567 | **70,7%** |

В сбалансированном аудите обнаружено 301 ложноположительное решение LLM и 85
ложноотрицательных. То есть модель гораздо чаще называет одним товаром две
лишь похожие карточки, чем пропускает настоящее совпадение.

## Raw score — ранжирующий сигнал, а не вероятность

Для дробных target выборка случайна внутри соответствующего положительного или
отрицательного диапазона. В таблице выполнен дополнительный пересчёт по
`category × exact target`; редчайший score `1/9` в выборку не попал.

| Raw target | Пар в корпусе | Проверено | Доля `audit = 1` среди разрешимых |
|---:|---:|---:|---:|
| `0` | 7 184 663 | 500 | 3,2% |
| `1/9` | 1 434 | 0 | — |
| `2/9` | 632 415 | 243 | 8,1% |
| `3/9` | 497 157 | 190 | 17,6% |
| `4/9` | 252 544 | 67 | 18,1% |
| `5/9` | 269 160 | 100 | 40,5% |
| `6/9` | 170 222 | 48 | 45,5% |
| `7/9` | 276 349 | 96 | 49,6% |
| `8/9` | 679 881 | 256 | 71,6% |
| `1` | 1 223 955 | 500 | 83,1% |

Порядок в целом монотонный, поэтому score полезен для ранжирования уверенности.
Но численно он сильно завышает вероятность совпадения по восстановленной
политике. Порог `0.5` особенно неудачен: `5/9…7/9` дают примерно 40–50%
настоящих положительных примеров. Даже `8/9` — только около 72%, а `1` — около
83%.

## Какие правила LLM нарушает

Среди 386 разрешимых ошибок в сбалансированной выборке:

| Тип ошибки | Число | Доля ошибок | Содержание |
|---|---:|---:|---|
| `GENERIC_OVERMATCH` | 135 | 35,0% | общий тип/бренд/цвет принят за один SKU без модельного якоря |
| `MODEL_VARIANT` | 114 | 29,5% | проигнорирован другой артикул, модель, цвет, рецепт или техническая версия |
| `MISSED_MATCH` | 77 | 19,9% | пропущены общий MPN, редкий дизайн или совпадающий физический fingerprint |
| `QUANTITY_BUNDLE` | 36 | 9,3% | одна штука спутана с набором, отличаются объём или комплект |
| `WRONG_ENTITY` | 16 | 4,1% | основной товар, аксессуар, часть или соседний подтип перепутаны |
| `BAD_SOURCE_FIELDS` | 8 | 2,1% | LLM последовала шумному полю вместо согласованного title/набора признаков |

Типичные примеры:

- `171798816420 ↔ 730144604442`, `target = 1`: тормозные детали Trialli
  `DF165101` и Smart.store `DF155101` — разные модели.
- `695784836603 ↔ 773094127513`, `target = 1`: микроволновки Bosch
  `BEL524MB0` с грилем и `BFL524MB0` solo.
- `661425037856 ↔ 395137022399`, `target = 1`: Synergetic `6 × 1 л` против
  одной бутылки `1 л`.
- `472446430826 ↔ 781684148512`, `target = 0`: один Somat Extra, 100 таблеток;
  вероятный false negative.
- `489626366239 ↔ 618475437680`, `target = 0`: одинаковый iPhone 16 Pro Max
  `8/512`, Desert Titanium, SIM + eSIM.
- `798863928254 ↔ 257698169928`, `target = 1`: кольца «Яхонт» с артикулами
  `145812` и `125546` и различающимся весом.

Общий паттерн тот же, что следует из человеческой инструкции: сначала нужно
доказать общую базовую модель, затем проверить hard-варианты категории. LLM
часто останавливается после семантической похожести названий.

## Насколько надёжен сам аудит

80 пар были повторно и вслепую размечены другим ревьюером: исходное решение не
показывалось. Полное совпадение, включая `U`, составило **78,8%**. На 74 парах,
где первый ревьюер дал бинарное решение, бинарное согласие равно **85,1%**,
Cohen's kappa — **0,695**.

По диапазонам полное межревьюерское согласие: 80% для exact negative, 85% для
exact positive, 90% для fractional negative и только **60% для fractional
positive**. Следовательно, вывод о слабости дробных положительных меток устойчив,
но десятые доли процента в итоговых оценках интерпретировать нельзя.

## Можно ли использовать все данные

### Подходящие сценарии

- pretraining или weak-supervision этап перед дообучением на human labels;
- candidate mining и обучение ранжированию;
- дополнительные отрицательные пары, особенно `target = 0`;
- distillation с пониженным весом и обязательной human-only validation;
- анализ ошибок и поиск hard negatives.

### Неподходящие сценарии

- замена human train/validation без понижения веса;
- оценка финального качества модели на LLM labels;
- калибровка вероятностей напрямую по raw target;
- бинаризация всех `target >= 0.5` как чистых положительных;
- балансировка класса преимущественно за счёт LLM positives без категорийного
  контроля.

### Рекомендуемая политика отбора

1. Сохранять raw target как confidence/ranking feature, а не как калиброванную
   вероятность.
2. `target = 0` использовать как наиболее надёжный weak-negative слой; всё
   равно оставлять меньший вес, чем у human labels.
3. `2/9…4/9` можно использовать как менее надёжные отрицательные/hard-negative
   пары. Не объединять их с exact zero без различия веса.
4. `5/9…7/9` не использовать как hard positive. Оставлять для unlabeled,
   consistency loss, повторной разметки или candidate mining.
5. `8/9` и `1` использовать только как weak positives. Фильтровать явные
   конфликты модели, MPN, количества, комплекта, цвета/рецептуры и применять
   категорийные веса.
6. Для одежды, обуви и галантереи требовать style/parent ID или очень
   специфичный общий дизайн; одного бренда и типа недостаточно.
7. Сравнивать ablation: human-only → `+ exact 0` → `+ vetted exact 1` →
   `+ fractional`. Выбирать стратегию только по component/item-disjoint human
   validation.

## Оценка текущего `prepared/mxbai_balanced`

Текущий подготовленный train содержит 388 833 LLM-пары:

- 118 795 с raw `0`;
- 267 501 с raw `1`;
- 2 537 с raw `8/9` — только для одежды.

Экстраполяция category × raw-target результатов аудита на этот конкретный
состав даёт:

| Часть supplement | Пар | Оценка согласия | Sampling-only 95% interval |
|---|---:|---:|---:|
| Weak negatives | 118 795 | **95,9%** | 93,8–97,7% |
| Weak positives | 270 038 | **77,8%** | 74,2–81,4% |
| Всё дополнение | 388 833 | **83,5%** | 80,9–86,0% |

Это экстраполяция, а не отдельная ручная выборка именно из supplement. При
крайних трактовках `U` точечная оценка всего supplement лежит примерно в
диапазоне 80,9–84,0%.

После внутренней балансировки итоговая сумма `sample_weight` LLM-строк равна
162 193 против 284 468 у human-строк: weak labels дают **36,3% всей loss mass**.
В положительном классе доля LLM ещё выше — **56,3% positive loss mass**. При
оценочной чистоте weak positives около 78% это агрессивно: базовый
`llm_weight = 0.35` не отражает окончательное влияние после категорийно-классовой
перебалансировки.

Первый безопасный эксперимент — оставить exact-zero дополнение, а positive LLM
mass снизить ниже human positive mass и возвращать её постепенно по результатам
human-validation ablation. Для одежды, обуви и галантереи exact-positive слой
лучше сначала отключить либо пропустить через отдельный rule/model filter.

## Ограничения

- Это сравнение с реконструированной политикой, а не с недоступной официальной
  инструкцией организаторов.
- Исходная human-разметка сама содержит редкие противоречия; они описаны в
  инструкции и не превращены в общее правило.
- Проверены title и JSON-атрибуты, но не изображения и не скрытый контекст
  генерации LLM labels.
- По 25 примеров на category × band достаточно для крупных различий, но мало
  для точного ранжирования соседних категорий.
- Sampling-only интервалы не покрывают систематическую ошибку инструкции и
  разметчика. Межревьюерская проверка лучше показывает этот дополнительный
  источник неопределённости.
- Для raw `1/9` нет ручных наблюдений; этот score составляет лишь 1 434 пары,
  или 0,013% корпуса.
